# Gemma 长文能力实验方案

日期：2026-11-08。状态：**待实施的方案**；本轮只生成可视化、检查公开题预算并设计实验，没有启动新 GPU 作业。

[结构化参数草案](protocol.proposed.json)便于后续冻结协议；它不是可直接执行的训练 recipe。

## 研究问题

在相同 Gemma 4 E2B Base、相同问答监督和相同推理协议下，完整长文训练能否比短证据训练，
更有效地利用远距离信息？第二阶段再检验保留文档结构的 CPT 是否提供额外收益。
成功标准必须在正式测试前固定；结果也可能无提升或下降。

Gemma 已有原生长上下文配置。本研究关注**有效使用长上下文的能力**，不以修改长度参数、
训练 loss 下降或能加载 128K 输入作为能力提升证据。4K / 8K / 16K / 32K 均以 Gemma 原生 token 计。

现有 [A100 试跑](../colab_sft_20261108/README.md)只证明 95–119 token 的训练、保存与重载可用。
现有 350 篇来源语料、31 篇审核包和 42 条公开题可作为工程基础；它们不等于已获准的正式训练集或完整基准。

## 1. 先做配对 SFT，再做 CPT

| 组别 | 初始化与数据 | 作用 |
|---|---|---|
| B0 | 锁定的原始 Base，无本项目训练 | 描述起点，不能单独分离指令微调与长文收益 |
| S-short | Base → 短证据 SFT，输入不超过 2K | 学到相同问题、答案和任务格式的对照 |
| S-long | Base → 完整长文 SFT，第一轮真实输入 4–8K | 主实验：长距离关联、干扰信息和全文定位训练 |
| C-shuffle → S-long | Base → 同源段落打乱 CPT → 相同长文 SFT | 第二阶段：内容学习与破坏结构的对照 |
| C-ordered → S-long | Base → 保留段序 CPT → 相同长文 SFT | 第二阶段：结构保留的增益 |

**第一阶段主比较是 S-long − S-short。** B0→S-long 混合了指令遵循、格式学习与长文训练效果。
正式实验从原始 Base 重新初始化，不接着训练 10 条 smoke 的 adapter。固定 Base revision
`433813a669639fd7eaa83155828e9000ed357d53`，首轮统一 BF16 + LoRA rank16 / alpha32，保持原生位置编码。

同一 QA 对的两个训练版本：问题、答案、来源、全部必要证据不变。
短版使用人工核实的必要证据及理解它所需的上下文；长版保留原文与必要结构。
短版是**训练控制用的 oracle evidence**，不是测试时的检索方法；测试时两组收到完全相同的长输入。
不能把答案所需证据截掉，再称它为公平短文本对照。

训练首轮聚焦四类可严格配对的任务：单文档证据定位、跨章节 2–3 跳关联、跨文档对照、表格与条件关联。
每类 pilot 目标 32 对 train / 8 对 dev。答案建议 64–256 token，实际长度和监督量均需冻结。
全局摘要不能保证压缩到 2K 后信息等价，所以先作为**独立公开测试任务**，不硬塞进配对训练。
无法形成保真短版的样本从两组同时排除并记录原因。

两组匹配 QA ID、监督答案、数据顺序、batch、optimizer steps、学习率日程和 seed。
正式模板编码后验证监督 token 数及标签序列；训练器再记录实际消费的 labels，不能只看准备阶段计数。
这匹配的是**监督量**，不是输入 token、FLOPs 或 GPU 时间。报告两组实际成本；如要主张效率优势，另做算力匹配实验。

## 2. 数据与独立性

1. 保留旧语料和旧 split 历史。先核查现有 158 对跨 split 重合候选及跨语言家族，再生成新版本来源锁。
   模板公式/公共样板与真正重复分别处理，不能把全部候选直接声称为污染，也不能忽略候选。
2. 以原始文档、书籍、仓库/项目和翻译家族为单位隔离。原 test 不回流 train；一篇来源派生的所有 QA 必须同 split。
   跨文档题绑定的来源连通分量必须整体隔离，不能只按单条 QA 随机分配。
3. 目标 pilot 至少 32 个 train 来源家族、8 个 dev 家族；正式阶段目标至少 128 / 16 个。
   每家族最多 4 对主训练题。实际达不到时报告缺口，不能复制题目凑数量。
4. 中英文比例先设 3:1、至少 4 个实际可用领域；这是待审核配额，不是已经构建的统计。
   来源过短时只构建主题相关、来源可追踪的多文档包，不用重复填充凑长文。
5. 每条训练答案、短版必要证据和来源许可均使用真实人工凭据；抽样二审记录与首次审核分开。
   原 31 篇仍 pending，之前批准的 10 条只限工程 smoke。AI 审核不能替代人工准入。
6. 在训练前对**最终整套测试来源**做全文/片段/家族去重，保留近重复候选处置记录；过去只检查 42 题不够。
   LongBench / RULER / BoolQ 的测试内容不参与训练、合成提示或训练数据选择。
7. [LongAlign-10k](https://github.com/THUDM/LongAlign)可作为后续公开训练数据参考；
   [当前数据仓库](https://huggingface.co/datasets/zai-org/LongAlign-10k)的原长度不是 Gemma token 预算。
   来源与许可证据、去重和审核不足时不进入本轮主对照；不直接照搬其训练环境。

## 3. 多方向测评

三个层次分别报告，不把异质基准混成一个总分。

| 层次 | 内容与指标 | 用途 |
|---|---|---|
| 公开主终点 | LongBench v1：hotpotqa、multifieldqa_en、narrativeqa、gov_report；前三者官方 QA F1，最后官方 ROUGE-L | 跨文档问答、文档问答、叙事问答与长报告摘要的迁移 |
| 受控诊断 | RULER 子集 niah_multikey_1、niah_multivalue、vt、cwe、qa_1；官方任务评分 | 多目标检索、多值、多跳变量追踪、聚合与长文 QA |
| 回归/补充 | BoolQ validation 短文本；中文 multifieldqa_zh、qasper；可容纳的 LongBench v2 | 短能力退化、语言差异、更难任务与地板效应 |

官方来源：[LongBench v1](https://github.com/THUDM/LongBench/tree/main/LongBench)、
[LongBench v2](https://github.com/THUDM/LongBench)、[RULER](https://github.com/NVIDIA/RULER)、
[RULER 任务配置](https://github.com/NVIDIA/RULER/blob/main/scripts/synthetic.yaml)、
[BoolQ](https://github.com/google-research-datasets/boolean-questions)。
LongBench v2 原文长度单位是 words，不能直接当 token；初期只做分层子集，不宣称完整榜单。

### 已做的公开样本容量检查

本轮对缓存中的 1550 条、8 个完整 LongBench v1 任务，核验来源哈希并重算原生 Gemma 预算。
以下是**官方 Base prompt + BOS + 官方生成预留**的分箱，尚未加入未来统一 chat 模板。
它只用于规划容量；既不是正式题目 ID 冻结，也不是实际模型评测。
完整证据见 [benchmark_budget_audit.json](benchmark_budget_audit.json)。

| 任务 | ≤4K | 4–8K | 8–16K | 16–32K | >32K |
|---|---:|---:|---:|---:|---:|
| qasper | 68 | 117 | 12 | 3 | 0 |
| hotpotqa | 5 | 22 | 118 | 55 | 0 |
| multifieldqa_en | 40 | 49 | 60 | 1 | 0 |
| multifieldqa_zh | 93 | 84 | 23 | 0 | 0 |
| gov_report | 14 | 64 | 94 | 25 | 3 |
| multi_news | 156 | 37 | 7 | 0 | 0 |
| narrativeqa | 0 | 0 | 61 | 48 | 91 |
| 2wikimqa | 23 | 119 | 55 | 3 | 0 |

这解释了为什么不能预设每个任务 100 道 8K 长题。主终点选题量充足的四项，目标各 50 道，共 200 道。
最终准入条件为 **实际完整模板输入 ≥8192 token，输入 + 官方输出预留 ≤16384**；
上述总预算分箱不等同于这一条件，必须重算。每项先留出最多 5 道独立 pilot 题，
正式 50 题是否可达以新预算/来源家族审计为准；不足时在看模型答案前修改并冻结新协议版本，不能偷偷换题。
在每任务内部按长度和来源分层随机抽样，selection seed 固定 20261108。

初始 pilot 的 60 道公开题：四主任务各 5 道，qasper、multifieldqa_zh、multi_news、2wikimqa 各 10 道。
后四项可使用较短自然输入；整个 pilot 只作探索，不与正式主终点混合。pilot 与确认集须按来源簇隔离。

RULER 用相同固定样本对比较模型，按 4K / 8K / 16K / 32K 报告，32K 必须先通过资源探针。
生成器、词表/外部材料 revision、seed 和 tokenizer 全部固定。若为 Gemma 改了 prompt 或长度控制，
记录为适配协议，不能声称与官方默认设置完全等价。
证据位置 10% / 50% / 90% 和移除必要证据实验单独做来源隔离的辅助诊断；修改官方题目后不混回官方成绩。

### 统一推理协议与分母

- 新增 versioned `gemma4_nothinking` 对话评测协议，对所有 SFT 组使用相同 token 序列、停止符和生成预算。
  B0 同协议只作描述，原有 Base raw completion 另列，二者不能直接混算。
- 首轮统一 BF16、greedy、batch1、无检索和静默截断；量化部署另作第二套实验。
  按各公开任务官方输出限额计预算；完整输入、生成长度、耗时、结束原因和模型/adapter 哈希全部保存。
- 固定题目 ID 后不重抽失败题。公开主指标将 OOM、超时、解析失败、缺失预测按零分纳入冻结分母，
  同时报告失败类型、覆盖率和成功条件下分数。正式数据集建库时超限排除的数量也必须展示。
- 私有自建 gold 需独立人工核实，AI 候选与公开基准分栏；不得用自建 quote-location 成绩替代推理能力。

## 4. 规模、资源与停止条件

| 阶段 | 训练 | 测试与目的 |
|---|---|---|
| 资源探针 | 新的训练专用已审材料，真实 4K→8K→16K；各至少 3 个 optimizer steps，分别测 forward/backward | 同时测 4/8/16/32K 推理；约10GiB显存的短样本结果不外推 |
| 探索 pilot | 128 对 train + 32 dev；S-short≤2K，S-long 4–8K；2 epochs、有效 batch8，每组32steps，seed17 | 每 checkpoint：公开60 + RULER 5任务×3长度×10=150 + BoolQ40；B0/短/长共750次预测 |
| 确认实验 | 512 对 train + 64 dev；相同固定步数128/组，seeds17/29/43；第一版仍4–8K，16K训练扩展另立版本 | 主公开200；qasper10/中文20（暂定容量）；RULER400；BoolQ200；七checkpoint合计目标5810次预测 |

确认实验的七个 checkpoint 是 1 个 Base + 两训练组各 3 seeds。LongBench v2 暂不计入5810，
若增加目标60题/模型则额外420次；所有数量均是待容量复核的预算目标，不是已完成结果或功效保证。
8K训练、16K测试检验一定长度外推；32K只有实际完成相同协议评测时才可报告结论。

A100 40GB 是已验证的短程平台。建议资源探针每项有明确超时、无 OOM，且整卡留至少约4GiB余量后才升级长度；
单独记录 allocator allocated/reserved 和整卡采样。若16K训练不适配，先完整做8K配对实验，
或新建两组都用相同 QLoRA 的版本，不临时只量化其中一组。

预算按各长度实测计算：
`训练时间 ≈ Σ(各桶 microsteps × 实测秒/microstep) + 校验/保存时间`；
`评测时间 ≈ Σ(各桶题数 × 实测秒/题) + 加载/归档时间`。
报告平均与慢样本分位数，不用本次97秒乘倍数预测长文成本。
建议 pilot 先设 **6 A100 GPU-hour 的整轮上限提案**，以探针后复算的预算决定是否足够；
若不足，训练前修订规模/协议，不能在某组表现不好时单独缩减。确认实验成本必须由 pilot 外推后另行确定。
这些是设计预算，本轮没有分配 GPU。Colab 断开后要保留进度、数据顺序和 RNG 状态，不能重跑后只挑最好一次。

## 5. 预先约定“有提升”的证据

主分数：每任务按官方评分归一到 0–100，然后四任务等权宏平均；它是异质任务的 score points，**不是总体准确率**。
主效应：相同测试题上 `S-long − S-short`，先对每 seed 计算，再报告三个 seed 的平均及逐 seed 值。

建议确认实验成功条件：

1. 主效应至少 **+3 分**，配对来源簇 bootstrap 的95%置信区间下界大于0；10000次重采样，分析seed固定20261109。
2. 至少两个 QA 主任务平均差值为正，且三个训练seed的主效应方向一致，避免只由摘要或幸运seed驱动。
3. BoolQ 短任务差值的95%区间下界不低于 −2 个百分点；样本不足以建立非劣时写“未能排除退化”，不能称无损。
4. 长度分层、失败率和 RULER 多跳/聚合结果支持相同解释；若只是单needle提升，仅声明检索诊断提升。

来源簇至少用相同原始文档/相同context哈希聚合，能识别书籍/项目时用更大的家族。
主CI对固定三个seed的平均差值在任务内按来源簇成对重采样；另列三个seed的散布，
不把同源多题当独立样本，也不声称三个seed充分覆盖训练随机性。
200题未必能检测3分差异：用独立pilot估计方差/有效来源簇数量，正式测试前确定是否扩容。
不得反复看确认集调整学习率、数据配比或选择checkpoint；固定最后一步作为主checkpoint，dev用于预定的诊断/调参阶段。

CI跨0、仅自建集合提升、频繁失败或短任务退化，分别报告“不确定”“仅局部提升”“资源限制”或“存在代价”。
这些也是有价值的研究结果，不能通过更换分母或事后改主指标变成成功。

## 6. 第二阶段：与预训练数据岗位直接相关的 CPT 证据

先完成并锁定 S-long 的统一数据/训练/评测，再从同一 Base 做 ordered 与 shuffled CPT；
两组使用同源文档覆盖、相同段内文本和模型设置，保持正式评测数据完全不可见。
建议从约2M有效监督token的小预算pilot开始，再依据趋势和实测决定是否扩至10M；这不是预设必然有效的数据量。

必须增加训练器级标签曝光计数，并处理跨块分词/边界/packing造成的数量差异；
必要时建立经过验证的稳定token单元与mask。单纯同样20steps或原文字符相同不够。
做不到严格配对时保留“非严格配对”标签，不下文档结构的因果结论。

依次看：CPT-only 的同源holdout NLL、统一 SFT 后的公开任务分数，以及 ordered−shuffled 的差异。
除了原来的2K窗口NLL，新增**相同末尾512个目标token**、分别给2K/8K/16K前文的条件NLL；
只对相同后缀评分并按来源簇统计。原有重置KV的2K窗口NLL只用于语言质量/遗忘监控。
整体做法可参考 [ProLong 的数据与消融研究](https://github.com/princeton-nlp/ProLong)，
其模型、训练规模与本项目不同，不能把论文效果转述为 Gemma 的预期收益。

- 各组每任务分数与配对增益95%CI；失败覆盖率并排展示。

- 短任务退化与长任务增益的二维图，颜色区分seed。

本方案先完成“长文SFT是否有效”的最小因果对照，再用CPT结构消融回答“什么长文数据策略有效”。
