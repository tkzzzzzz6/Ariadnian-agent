## 本轮预实验规模

| 项目 | 原草案 | 当前准备 |
|---|---:|---:|
| train / dev 问答对 | 128 / 32 | 32 / 8 |
| train / dev 来源连通组 | 至少32 / 8 | 8 / 2 |
| 每臂 epochs / optimizer steps | 2 / 32 | 2 / 8 |
| seed | 17 | 17 |
| 公开题 / checkpoint | 250 | 已冻结250题：LongBench60、RULER150、BoolQ40 |

降低初轮规模是为了形成真实可审阅的样本，未重复内容填充配额。完整方案仍缺96条train、
24条dev。数据来自12份原始文档，涵盖编程、机器学习、农业、生命科学；32题英文、8题中文，
dev目前只有英文。来源组以文件/章节/DOI及跨文档连通关系定义，不把同一书籍或仓库的
多个文件称为多个完全独立领域。跨文档训练的4题集中于CSV与Decimal，后续需扩展主题。

两臂问题、答案、来源、顺序一致，必要证据均出现；不增加重复块凑长文。
排除97份涉及待判定跨划分重合的来源，未选原test。短版是训练对照的oracle evidence，
测试时所有模型收到同样的公开长输入。长输入并不自动意味着每道题都有远距离依赖。

公开题原生chat输入为70–16325token，250题全部满足输入加输出预算不超过16K；20道primary
LongBench题的输入至少8506token。RULER的qa_1仅来自Normans一篇文章，按一个来源簇计，
不计算独立来源置信区间。隔离pilot来源后，NarrativeQA符合当前正式长度条件的保留题只剩12道，
不足原定50道；正式实验必须先补充独立来源或重新预注册长度范围，不能回收pilot题填数。

固定审核包的 `review_packet.lock.json` SHA256：

AI检查、内容哈希和预览通过不授予训练准入。先前10条试跑的审批没有扩展到本批40组。

## 执行顺序与当前状态

1. 本地固定长短配对数据、公开测试输入和推理协议；记录真实长度、来源和失败分母。
2. Colab OAuth重新登录成功后，创建独立命名A100会话，先做4K/8K/16K训练负载与4K–32K推理资源验证。
3. 本批人审通过后，两臂从同一Base分别训练，核对实际消费的监督标签与数据顺序，再保存/重载adapter。
4. 原始Base、短SFT、长SFT在相同250题上评测，绘制分项成绩、差值区间与成本图。
5. 下载并校验归档，停止本轮创建的GPU会话。资源验证和预实验共用六小时预算上限；确认性多seed实验与CPT另行开展。

此前云端前置检查返回 `RefreshError: invalid_grant`，尚未分配本轮GPU；用户选择暂缓后未重试登录或查询会话。登录修复脚本
`experiments/colab/reauthenticate.py` 使用已安装官方CLI的授权流程，仅在本机终端输入授权码，
成功后才替换旧凭据，不创建GPU。该脚本保留供日后恢复使用，当前无需执行。

资源探针只在可丢弃LoRA上跑工程负载，训练部分每个长度3次真实反传/更新、仅32个监督target；
因此不能把探针显存等同于完整SFT峰值，也不把它算作数据训练收益。完整SFT另行审计真实标签、
显存和耗时。所有失败与超时均保存，不用缺失数据画0准确率或预期提升曲线。
