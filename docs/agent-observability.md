# Agent 运行详情

Agent 面板底部的「运行详情」显示当前任务的执行过程；「历史」中每个任务也有独立入口。打开详情不会离开或停止当前任务。此功能对应 Issue #9。

## 日常使用

1. 运行综述、分节写作或审稿任务。
2. 底部状态条显示当前进展、累计执行时间和用量；点击「运行详情」。
3. 选择一次运行，查看步骤、工具和模型调用。展开步骤可看内部标识、耗时和调用次数；展开工具可看结果数量、来源、缓存及异常；展开模型可看 Token、首次正文和首次推理内容时间。
4. 出错时展开失败记录，点击「复制诊断摘要」交给维护者或编码 Agent。浏览器不允许剪贴板访问时，可以在摘要文本框内手动复制。
5. 需要确认、停止后继续或重试时，返回原任务卡片操作。详情页不会任意重跑工具，也不会因回看历史触发付费模型请求。

一次开始或恢复对应一个运行 ID。同一任务保留多次运行，已保存的旧步骤不会累计进新运行。任务底部统计仍是任务累计值；详情中的统计只属于所选运行。并行章节有各自的步骤和子调用，单步耗时不能相加作为任务总耗时。

## 观察界面的使用方式

- 顶部固定显示当前任务、正在执行的步骤、等待模型或生成正文等真实状态。等待用户时给出待处理事项和「前往任务确认」，返回原卡片处理；不会代替用户确认或自动重新执行。
- 正常完成的步骤默认收起，只加载摘要；当前步骤、等待确认和异常默认展开。手动展开或收起的选择在刷新时保留，子调用按需读取。较长步骤的调用每页 50 条，概览最多展示 500 个步骤和 100 条异常。
- 点击图钉「固定到观察侧栏」后，可以同时审阅正文和观察执行。原 Agent 始终保留挂载，固定、放大及切换页签不会中断流式写作。隐藏观察页签或关闭抽屉会停止其轮询；切换文档时清除固定对象。观察历史任务时会明确显示任务主题，避免与新任务混淆。
- 「耗时」使用同一时间轴显示步骤，重叠条表示并行，点击条目可以展开对应步骤。中断记录的轴到最后已记录事件，不虚构结束时间。时间条不代表完成百分比。
- 「跳到异常」在整个运行中定位异常，能打开不在第一页的调用；「仅看异常」用于集中检查。只有同一模型请求的后续尝试确实成功时才标为「已恢复」，并归组显示尝试；旧记录没有请求关联时不会猜测恢复关系。并行章节的失败单独计数，不将函数正常返回等同于章节写作成功。
- 开启内容采集后，检索工具展示检索词、论文或证据摘要，引用检查展示检查量、问题量及可定位的原句。正文发生变化或匹配不唯一时会说明无法准确定位；论文按钮使用现有预览入口。结构化结果最多保留 6 项，并按字段长度限制缩减，原始内容放在「技术详情」。
- 模型推理与正文分别展示，可暂停自动跟随或回到最新。长流式内容保留开头与最新片段，并标明中间省略；每秒最多保存一次有变化的内容快照，结束后再刷新。模型没有提供推理或用户没有开启采集时明确说明，不生成替代思考。
- 长时间没有执行事件时显示最后活动间隔，不直接判定卡住或失败。流式接收活动只在内存中更新时间，不逐 Token 写日志。

等待确认的时间与执行时间分开；恢复后，旧运行的等待时长截止于下一次运行开始。进程退出时未完成的记录标记为「意外中断」，不虚构结束时间。旧任务显示无可用记录，不能根据旧汇总还原时间线。

## 工具、执行说明与推理信息

工具包括学术检索及各检索来源、证据检索、证据与笔记收集、全文下载、解析索引、引用检查和批注。这里也记录程序直接执行的函数，并不要求模型使用 function calling。检索来源的并发线程传播追踪上下文；单一来源失败或回退会保留记录。

「最近进展」来自应用实际发出的执行事件，例如检索完成、开始自查引用；它不是模型内部思考。模型调用另外接收服务明确返回的 `reasoning_content` 或文本 `thinking_blocks`，与正文分开处理。不会解码加密思考块，也不会额外调用模型生成仿真的思考过程。

流式调用区分等待响应、收到推理内容和生成正文。没有服务事件时只显示等待响应，不能认定模型正在思考。同步调用只能在服务返回后显示推理信息，不能准确测量首次推理内容时间。Token 未返回时显示未知；离线演示值标为估算；推理 Token 可能已含在输出 Token 中，不能重复相加。

应用可见的 JSON 兼容重试、长度限制重试及备用模型尝试分别记录。SDK 内部重试可能不可见，不根据配置次数推算实际请求次数。

## 内容采集与保留

在运行详情中打开「记录设置」：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 详细输入、输出及推理内容 | 关闭 | 开启后只影响之后开始或恢复的运行 |
| 基础记录保留天数 | 30 天 | 任务运行、步骤、工具和调用元数据 |
| 详细内容保留天数 | 7 天 | 采集的输入、输出和推理文本 |

配置键为 `TRACE_CAPTURE`、`TRACE_RETENTION_DAYS`、`TRACE_DETAIL_DAYS`，可通过已有设置接口或环境变量配置。天数范围 1–365；执行设置锁定策略。采集时每个输入、输出、推理字段最多保留 2,000 个字符，并标记截断；不采集系统提示、请求头、签名和加密推理块。配置中的密钥及常见认证字段进行脱敏。用户仍应按实际数据敏感程度决定是否开启内容采集。

诊断摘要不包含完整提示、结果或推理文本，但会包含脱敏后的错误、运行标识及调用元数据。它用于定位问题，不是完整重放文件。外部服务状态和模型非确定性都可能影响再次执行的结果。

过期记录在服务启动及新运行时清理，跳过活跃运行。也可手动清理一个已结束或暂停任务的全部追踪记录，需在界面确认。清理不删除文献、文档、已有用量日志和 LangGraph 检查点。SQLite 文件可能复用已释放空间，不保证删除后物理文件立即缩小。

## 存储与开销

追踪存储在数据目录的 `traces.sqlite`，独立于 `aria.sqlite` 和 `checkpoints.sqlite`。每次运行的有界队列最多 2,048 项，每批最多处理 50 项，短事务写入。单次运行最多接受 20,000 次记录更新，超过上限或写入失败标记不完整，业务继续执行；结束时最多等待 0.5 秒刷新。没有逐 Token 写入，流式文本只在内存中保留有长度限制的片段；开启内容采集时每个活跃调用最多每秒保存一次片段快照。

运行中的基础状态沿用现有 SSE。观察界面读取不含完整内容的运行概览，仅展开步骤才分批读取调用、展开调用才读取详细内容；活跃运行约每 1.5 秒刷新，已完成步骤不会随每次轮询重复读取。终态停止轮询，SSE 状态变化或重新激活面板时刷新。隐藏浏览器页面、隐藏观察页签及关闭详情均停止读取数据。接口错误会明确提示并允许重试，不将读取失败解释为任务失败。

当前运行状态依赖应用进程内的执行注册表，与现有 Agent 执行机制一致，适合项目现有单服务进程部署；不作为多进程共享调度器使用。

## 验收步骤

先运行 `npm test`、`npm --prefix frontend run build` 和 `npm run eval -- --offline --source fixture --no-save`。测试禁用开发者本机 `.env` 自动加载，使用临时数据；模拟服务响应不会产生付费模型调用。

手动体验可运行 `npm run demo`，使用演示数据与估算 Token：

1. 综述检索后等待选文献：确认等待状态、工具调用数量和节点耗时；选文献继续后应出现另一次运行。
2. 分节写作选择并行模式：两个章节及各自模型、检索、引用检查应正确关联；查看详情不能停止写作。
3. 运行中停止，等待保存后继续：前次显示停止，新次不重复计入前次完成的步骤。
4. 开启详细内容采集后开始新任务：可展开输入输出；旧任务不补造内容。演示模型没有真实推理信息。
5. 在受控模拟测试中返回推理文本或错误：推理不进入正文，未知 Token 不显示为零，错误可定位并复制摘要。
6. 从历史打开详情；清理已结束任务追踪后，仍能恢复其任务检查点。

真实模型的推理字段、用量及延迟需要使用相应提供商配置单独验收，离线模拟不证明所有提供商都支持这些字段。
