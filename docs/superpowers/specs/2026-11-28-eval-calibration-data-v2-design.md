# 下一阶段：评测校准与配对数据 v2

维护者已授权按上一阶段建议实施；关联 Issue #15。先交付本地准备，真实训练受新批次人工准入约束。旧40对的批准继续有效，不覆盖新增或修改的记录。

## 目标与选择

沿用独立实验环境和既有训练/测评守卫。选择“旧250回归 + 独立开发校准 + 来源隔离确认集”，而非修改旧提示词重算旧分数，也不直接扩大训练掩盖格式失效。配对数据目标128train/32dev，来源不足时明确报告，不复制凑数。

本轮先保留既有模型、原生nothinking模板及官方评分实现。校准只在开发集比较预先声明的输出预算/少样本提示配置，按有效格式与执行完整性选择；不以确认集成绩调参。模型身份、特殊token、停止符和固定SWIFT模板另作审计，不宣称静态核验等于实际推理通过。

## 评测数据

重建锁定LongBench/BoolQ来源池，排除旧250的ID、来源关联组、规范化全文和长段落重合，并对完整的350篇候选来源做同口径审计，冻结每篇哈希；最终v2所用来源必须是这个范围内的逐字节等价子集，确认封存前重新核对。新增或改动来源必须重新分区及封存。LongBench主任务继续要求原生输入至少8192，输入加官方输出预算不超过16384；次任务保留总预算上限，不截断。选择使用seeded ID hash，与答案或模型成绩无关。

初始目标开发40题（LongBench八任务各2，BoolQ24）、少样本示范2题、确认160题（LongBench八任务各10，BoolQ80）；均按来源组隔离。实际缺额明确输出。原RULER150保留回归，不冒充新生成确认题；新的生成器种子/文章覆盖另行锁定。NarrativeQA历史reserve条数不等于独立来源族容量；按照新分区实际审计报告缺额，不预设一定有12个独立族。

校准配置仅由固定revision的Base、bf16、无adapter选择；90%格式门槛仅用于该Base开发校准，不要求各训练臂达到门槛后才计分。后续各臂/seed统一沿用这一配置，不按各自成绩另选。计划、原始输入、模型、adapter=None、量化、生成配置及逐题哈希须与真实加载收据绑定，不允许混用结果。

开发BoolQ预声明四配置：原8-token、32-token、64-token、2-shot/32-token。示范来源不进入开发/确认计分。使用原严格整段yes/no解析，另外报告格式、空输出/失败和有效格式下的正确性。格式有效率至少90%、执行完整才可推荐配置，按预声明优先级选择，不按答题分数选配置；未达到则校准未就绪。

确认集先锁ID/来源与内容，协议选择后另生成封存契约；不得把预备记录标为已完成确认实验。任何真实GPU调用前均验证实际模板、输入和依赖环境。

## 数据 v2

复用原始来源与人工可审阅证据格式，扩充中文、聚合、多证据和跨文档候选。相同配对的问题/答案/来源/split/顺序必须一致，长输入仅增加真实不同来源块。连接来源族不跨split，每族最多4个问题；拒绝精确重复QA，报告语言、方向、来源族与长度分布。

新审核包展示完整来源/许可、证据和两臂全文，全部新记录保持pending；只复用可验证仍相同的旧批准，不代替新内容批准。原builder里针对旧40条的固定文案改为由实际统计生成，历史HTML不重写。来源、规格、审核包、tokenizer、准入状态和哈希分别保存。
