# 按本地推理显存分档的 CPT 实验计划

状态：计划与选型，尚未执行 CPT。表中资源数字是工程预算，未经模型推理或训练实测。

训练代码、配置、脚本与测试集中在独立的 `experiments/ms_swift/`，汇总记录在 `experiments/results/`。
操作步骤见[MS-SWIFT 使用说明](ms-swift-gemma4.md)；CPT 已有准备流程，SFT 当前仍为下文的实验设计。

目标是使用服务器训练，在消费级显卡上运行训练后的模型，并同时验证数据策略收益、量化损失和部署成本。
本地目标包括 8GB 的 RTX 4060 Ti / RTX 4060 Laptop 等设备，以及 16GB 消费级显卡。
本机只读硬件查询记录为 RTX 4070 Laptop、8188 MiB 显存；它可承担 8GB 档实测，速度结果不能冒充 4060 的结果。

## 当前首模型

用户已确定第一阶段使用 [Gemma 4 E2B Base](https://huggingface.co/google/gemma-4-E2B)。
先完成该模型的部署验证、训练数据整理与训练对照，其他模型保留为后续候选，不在首阶段并行展开。
8GB 本地量化推理仍为待实测目标；选定模型不等于已经通过部署验收。

后续模型候选如下，每款都需要从自己的同一初始 checkpoint 做训练前后对照：

| 目标档 | 模型 | 作用 |
|---|---|---|
| 8GB | [Qwen3.5-2B-Base](https://huggingface.co/Qwen/Qwen3.5-2B-Base) | 较新混合注意力小模型 |
| 8GB | [Granite 4.0-1B-Base](https://huggingface.co/ibm-granite/granite-4.0-1b-base) | 实际约 1.63B 参数，纯文本稠密模型，支持中英 |
| 16GB | [Qwen3.5-4B-Base](https://huggingface.co/Qwen/Qwen3.5-4B-Base) | 同家族规模对照；完整仓库约 4.66B 参数 |
| 16GB | [Gemma 4 E4B](https://huggingface.co/google/gemma-4-E4B) | 不同家族对照；完整权重约 8B，不能按名字视为普通 4B |

工程冒烟可先用 [Qwen3.5-0.8B-Base](https://huggingface.co/Qwen/Qwen3.5-0.8B-Base)。
成熟对照可补 [Qwen3-1.7B-Base](https://huggingface.co/Qwen/Qwen3-1.7B-Base)。
首轮不将所有备选都展开成训练任务。

## Gemma 4 E2B 的训练方法选择

CPT 属于广义的继续训练或微调；研究报告中仍明确称为继续预训练，以区分训练目标。
训练目标、参数更新方式、部署压缩是不同维度：

| 维度 | 方法 | 当前用途 |
|---|---|---|
| 训练目标 | CPT：原文下一 token 预测 | 比较长文结构、序列组织和数据配比 |
| 训练目标 | SFT：指令与参考回答 | 学习长文问答、摘要、证据引用和缺信息拒答 |
| 训练目标 | DPO：偏好对优化 | 有可靠 chosen/rejected 数据后再评估 |
| 训练目标 | RL/GRPO：奖励驱动训练 | 有可靠奖励和在线采样条件后再评估 |
| 参数更新 | 全参、LoRA、QLoRA | 可与不同训练目标组合；LoRA 不是 CPT 的替代目标 |
| 部署处理 | Q4/Q5 量化与导出 | 训练后控制本地显存和质量损失 |
| 无权重更新 | 提示词、RAG、上下文选择 | 保留为应用效果与成本对照 |

推荐先以 LoRA 建立 SFT-only 基线，并保留 CPT+SFT 的研究对照。三组从同一 Gemma 4 E2B Base 出发：

| 组别 | 流程 | 回答的问题 |
|---|---|---|
| A | Base → SFT | 直接任务训练的基线 |
| B | Base → 打乱段序 CPT → 相同 SFT | 相同语料下的组织方式对照 |
| C | Base → 保留章节顺序 CPT → 相同 SFT | 数据组织策略是否产生额外收益 |

B/C 正式对照应使用相同文档、匹配的 CPT 有效 token 预算、序列长度、更新方式和优化设置；各组的 SFT 数据与预算相同。当前 MS-SWIFT 文本导出仅保证两臂源片段一致，重排可能改变 BPE 和序列数量，属于非严格配对的试跑准备。固定步数不能证明等 token，完成预算匹配前不能据此认定结构策略收益。
C 与 A 比较反映增加该 CPT 阶段后的净变化，包含额外训练计算，不能称为等总算力对照；C 与 B 比较用于检验序列组织因素。
原始 Base 和 CPT-only checkpoint 另留作语言建模指标与研究诊断。

Gemma Base 本身不提供完整聊天模板。SFT 需固定正确的模板、特殊 token 和损失范围，不能直接沿用无模板的 CPT 文本格式。
Google 提供了 [Gemma 文本 SFT 与 QLoRA 教程](https://ai.google.dev/gemma/docs/core/huggingface_text_finetune_qlora)；教程中的短序列示例不等于本项目 8K 训练的显存验证。
已单列 BF16 LoRA 与 QLoRA 的 4K/8K smoke 配置，见[实验操作说明](gemma-experiment-workflow.md)。
实际选卡前比较两种方式的资源测量，并核对未量化 embedding/PLE 的精度和训练范围；配置存在不代表 GPU 运行已验证。

SFT 需要单独整理训练数据。现有 AI 生成、未独立人工核验的 QA 仍是候选，不能直接标为可靠训练 gold；公开 benchmark 及其参考答案只作评测。
强模型可以辅助生成训练回答，经来源核对和内容复核后用于序列级蒸馏式 SFT，不能把生成本身当作验证。
DPO/RL 当前缺少可靠偏好数据或奖励依据，不在第一轮加入。

## 本地推理资源预算

统一假设为四位量化、纯文本、单并发、8K 总 token 上限、兼容的 GPU 后端；总 token 包括输入和输出。
范围为估算的运行预算，包含权重、KV/递归状态及工作空间，不是已测峰值。桌面和其他程序占用另计。
具体量化方式、保留精度的模块、预填充批次和后端实现会改变数字。

| 模型 | 本地运行预算（GiB，估算） | 第一轮部署长度 |
|---|---:|---|
| Qwen3.5-0.8B-Base | 2–4 | 4K、8K |
| Qwen3-1.7B-Base | 3–5 | 4K、8K；通过后测 16K |
| Granite 4.0-1B-Base | 3–5 | 4K、8K；通过后测 16K |
| Qwen3.5-2B-Base | 3–6 | 4K、8K；通过后测 16K |
| Gemma 4 E2B | 4–7 | 8GB 先测 4K/8K；16GB 再测更长 |
| Granite 4.0 Micro Base | 4–7 | 16GB 档优先，测 8K/16K |
| Qwen3-4B-Base | 4–7 | 16GB 档测 8K/16K，再测 32K |
| Qwen3.5-4B-Base | 5–9 | 16GB 档测 8K/16K，再测 32K |
| Gemma 4 E4B | 7–11 | 16GB 档先测 8K，再测 16K/32K |
| Gemma 4 12B | 9–14 | 16GB 条件备选，先测 4K/8K |

Gemma 4 的官方四位加载预算分别约为 E2B 2.9GB、E4B 4.5GB、12B 6.7GB，但不包含上下文缓存等完整运行开销，不能当作训练或长文推理的总显存。
见 [Google 内存说明](https://ai.google.dev/gemma/docs/core)。

长窗口支持上限不等于上述设备可以按该长度实用运行。8GB 的部署通过条件还包括为桌面和波动保留余量；靠 CPU offload 或交换内存才运行成功的样本需单独分类，不能标为全 GPU 部署通过。

Gemma 4 26B-A4B、31B、Qwen3.5 35B-A3B 等大总参数模型排除出 8GB/16GB 主线。
7B/9B 模型可以在较短上下文、合适量化下运行，不按参数量一律否定，但首轮不优先展开。

## 服务器训练

训练显存和本地推理显存分别报告。初始训练预算规划如下，均不是最小显存承诺：

| 训练任务 | 服务器试测卡档 |
|---|---|
| 0.8B–2B，8K LoRA CPT | 24GB–48GB |
| Qwen3.5-4B / Granite Micro，8K LoRA CPT | 32GB–48GB，必要时 80GB |
| Gemma 4 E2B / E4B，8K LoRA CPT | 48GB–80GB |

第一轮统一语言建模目标和更新方式，优先 BF16 LoRA；不是问答对的 answer-only SFT。
全参 CPT 是另一个配置，应单独测量显存和训练效果。
训练器需验证目标模型、混合注意力、重计算和省内存损失的支持，不能将新模型直接套入旧配置。

现有筛后语料中 train 划分为 281 篇、2,595,822 个 Qwen2.5 参考 token；当前构建用途为 assessment，训练准入、内容复核与训练版导出尚未完成。
训练版只使用获准的 train 文档。开发集、测试集与公开 benchmark 不进入 CPT。
每个目标模型使用自身固定版本 tokenizer 重新编码，不把参考 token 数直接当作原生训练 token 数。

同一模型的对照为 M0（未 CPT）、A（保留文档/章节顺序 CPT）、B（同样文档、预算，仅打乱段序）。
A/B 固定训练序列长度、有效 loss token 预算、优化器设置和随机种子。先进行小规模验证，再决定数据与重复实验规模。
一款模型在多个部署档都通过时，复用同一训练产物，不为每张显卡重复 CPT。

## 训练、量化、部署的评测矩阵

每个模型保留：M0 BF16、M0 Q4、CPT BF16、CPT Q4；A/B 两种训练策略分别评估。
Q5 可用于量化损失较大时的补充测试。先保留可复现的合并/转换记录，再导出量化版本。
量化权重不会自动量化 KV，KV 精度和容量另行记录。

| 方向 | 测量与报告 |
|---|---|
| CPT 效果 | 留出长文 loss、公开任务得分；同一模型相同精度下训练前后比较 |
| 数据策略效果 | A/B 同预算、同评测协议比较，保留负结果 |
| 量化损失 | 同一 checkpoint 的 BF16 与 Q4/Q5 比较；不混进 CPT 收益 |
| 长度范围 | 4K/8K 起步，通过后增加 16K/32K；超过原生窗口另设扩窗协议 |
| 运行资源 | CUDA 分配与保留峰值、进程显存、CPU/RAM 占用、GPU 驻留及 offload 情况 |
| 运行速度 | 预填充 tokens/s、首 token 等待时间、解码 tokens/s、失败率 |
| 硬件差异 | 桌面/笔记本 GPU 分开记录型号、显存、功耗条件与后端版本 |

公开任务使用固定题目和官方指标。为不同窗口预先冻结共同可容纳子集；明确修改上下文的预算协议另报。
现有 42 题作为开发诊断，正式结论需扩大并封存测试子集。
Base 模型使用匹配的完成式评测；若后续加相同 SFT，应将 CPT-only 与 CPT+SFT 结果分开。

所有模型的本地总显存和速度目前均未实测，不能把本计划表当成通过记录。当前已有的 132 次公开基准 API 调用也不属于 CPT 或本地部署结果。
