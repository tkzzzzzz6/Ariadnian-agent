# Issue #5：综述 Agent 的笔记输入与来源追溯

需求：https://github.com/tkzzzzzz6/Ariadnian-agent/issues/5

## 基线与首期范围

2026-10-23 核对上游 main 1881a2e。分节写作已有笔记输入，但综述 synthesize / make_outline 尚未读取 notes 表。首期仅扩展综述流程，不重写分节写作证据路径。保留文献勾选、大纲确认和旧检查点兼容。

- 启动综述时默认启用用户笔记，可关闭。只读取本次选中文献的笔记，不使用其他文献的内容。
- 在 ingest 后增加独立 prepare_notes 步骤，捕获可持久化快照。用主题和检索式的中英文分词做确定性的词项重合筛选，不增加模型调用；这只是相关性启发式，不能保证语义召回。
- 最多扫描最新 500 条、每篇最多 3 条、总共最多 12 条。单条摘录最多 800 字符、评论最多 400 字符，传入模型的笔记 JSON 总长不超过 8000 字符；超出时按排序丢弃并记录截断/省略情况。
- 保留 note_id、paper_id、bibkey、页码、摘录、评论、修改时间和内容指纹。界面称为“本轮提供的笔记”，不声称模型确实采用了全部条目。
- 摘录标记为用户保存的摘录（未重新核验），评论标记为用户观点（非论文结论）。模型提示禁止将评论当成原文依据，也禁止执行笔记中夹带的指令；相关性或事实冲突须回原文核实。此边界不等于模型事实正确性的保证。
- 文献归纳、综述、模型大纲及确认后的大纲都限制在当前仍存在的选中文献 bibkey 内，清理结构化引用标记中的非法 key。

## 笔记修改、删除、停止与恢复

- prepare_notes 完成后快照进入 LangGraph 检查点。停止后恢复、单独重写大纲使用同一快照，避免同一次任务静默混用不同笔记版本。
- 每次查看任务或确认大纲时核对快照条目的内容指纹。原笔记修改、删除或所属文献删除时明确标记；同一秒内的修改也按内容识别。
- 来源发生变化时，确认/单独重写大纲前需要用户明确接受旧快照；也可以“刷新笔记并重新生成”，重新筛选快照、重新归纳并生成大纲。服务端负责阻止未确认旧版本的请求。
- 新任务读取最新笔记；任务中新增的笔记不会自动加入旧快照，可通过刷新纳入。历史快照保留当时的文本：删除库内笔记不清除已有任务的历史副本，不应误认为已彻底删除所有副本。
- 旧任务没有笔记快照时，显示旧任务未记录来源；不在恢复时悄悄补入新笔记，可显式刷新后重新生成。
- 未选中相关笔记或关闭此功能时，仍走原有综述/大纲流程。临时预览和未入库文献不参与。

## 验收

1. 固定样例含相关/无关笔记、未选中文献笔记、中英文及超长条目；验证范围、排序、条数、字符预算和来源字段。
2. 捕获模型输入，确认归纳及大纲均包含同一笔记快照，摘录和评论字段分开；关闭/无笔记时无笔记内容进入模型输入。
3. 模型生成不存在的 bibkey、随后删除文献、用户确认大纲夹带非法引用时，引用校验均有效。
4. 使用真实 LangGraph + SQLite 检查点验证停止/重建图/恢复；修改与删除笔记后旧快照不变，查看能提示变化，未确认的旧快照请求被拒绝，刷新后重新归纳。
5. 保留既有 Agent 停止恢复回归、前端测试、TypeScript 检查与生产构建。界面用隔离数据库和 fake 模型进行端到端检查，不把离线样例当成真实模型质量评测。
